## Why Rust is harder to host than most games

Most survival games are fairly predictable. Rust is not. Three things make it demanding:

1. **Memory grows during a wipe.** Every wall, door, box and deployable is an entity. A fresh map might use a few gigabytes, but a busy server can double that by mid-wipe.
2. **It leans on single-core CPU speed.** A modern Ryzen or EPYC core at high clock speeds matters more than a large number of slow cores.
3. **Popular servers attract DDoS attacks.** If your host treats DDoS protection as an add-on, you will find out the hard way.

So when you compare the best Rust server hosting providers, look past the headline price. Ask how much RAM you get, what CPU sits behind it, and whether wipes and plugins are easy to manage.

## How much RAM does a Rust server need?

This is the question I get asked most, so here is a simple guide based on what the hosts themselves recommend:

- **6GB to 8GB:** a private server for a handful of friends, or testing.
- **10GB to 12GB:** up to about 50 players on a vanilla map of 3,500 to 4,000.
- **12GB to 16GB:** 50 to 100 players, or a vanilla-plus server with a few plugins.
- **16GB to 32GB:** 100+ players, heavy plugin stacks, or 2x and 5x gather rates.

Hostinger's own help centre recommends at least 12GB for the best performance, Nodecraft suggests 12GB for most vanilla groups, and Apex calls 4GB the bare minimum. Map size and entity count matter more than player count, so a 30-player server on a big map can need more memory than a 60-player server on a small one.

## Rust dedicated server basics: wipes, plugins and ports

- **Forced wipe:** Facepunch's monthly update lands on the first Thursday of every month, and every server must wipe the map then.
- **Oxide vs Carbon:** Oxide (uMod) has the biggest plugin library. Carbon is newer, performance-focused and runs most Oxide plugins. You can only run one at a time.
- **Default ports:** 28015 for the game, 28016 for RCON and 28082 for the Rust+ companion app.
- **Self-hosting:** the Rust dedicated server is Steam app 258550, installed with SteamCMD.

## 5 mistakes to avoid when renting a Rust server

I have seen the same mistakes again and again from owners who picked a host in a hurry. Avoid these and almost any host on this list will serve you well.

1. **Buying for wipe day instead of wipe week.** A server that feels smooth with a fresh map can stutter by day four. Size your RAM for the busiest point of the wipe, not the first hour.
2. **Comparing slot prices without checking RAM.** "$0.50 per slot" means nothing if the plan behind it only has a few gigabytes of memory. Always ask how much RAM each slot tier includes.
3. **Ignoring the location.** A great server in the wrong region still feels laggy. Look at where most of your players live and pick the closest data centre.
4. **Skipping a real load test.** Use your refund window properly. Invite friends, build bases, run your plugins and watch performance before the window closes.
5. **Forgetting about forced wipe day.** Every server must wipe on the first Thursday of the month. If your host has no wipe scheduler, set a reminder or you will be wiping by hand at an awkward hour.

None of these are expensive to avoid. They just take ten minutes of thinking before you click buy, and they are the difference between a community that grows and one that drifts away after the first laggy raid.
